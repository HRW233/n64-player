n64/player

An N64 emulator started from a written milestone plan instead of a blank cpu.c. The integer core, FPU, TLB, PI DMA, the RSP scalar core and task dispatch are in and measured. No frame has been rasterized yet, and this page says so instead of showing a screenshot.

01 What actually runs

unit where proven by
Bus, RDRAM, cart window src/bus.c big-endian stores, kseg0/kseg1 aliasing
ROM loader src/rom.c z64 / v64 / n64 byte orders normalise to one image
R4300i integer core src/cpu.c delay slots, signed vs unsigned, add overflow → ExcCode 12
COP1 FPU src/cpu.c double round-trip, all 16 compares, bc1t through its delay slot
TLB and translation src/cpu.c TLBWI maps a page; a miss takes the refill vector
PI registers and DMA src/bus.c PI_WR_LEN copies cart bytes into RDRAM
Exceptions src/cpu.c BEV/EXL vectors, EPC, ERET per EXL/ERL
SP DMA src/bus.c RD_LEN and WR_LEN move bytes between RDRAM and IMEM/DMEM
RSP scalar core src/rsp.c 32-bit MIPS, no delay slots; vector ops halt by name
Task dispatch src/rsp.c ucode DMA'd to IMEM, run to its break, list checked in DMEM
Boot path src/boot.c cart IPL3 from DMEM drives PI DMA and jumps to entry
Disassembler src/cpu.c trace output, --trace on the CLI

02 What it cannot do

blocked on input that must not be in this repository

  • The PIF / IPL1 boot ROM. Nintendo's, and not shippable. 0x1FC00000 reads as zero here, so a commercial cart stops before its first instruction. No amount of CPU accuracy changes that.
  • The CIC variants' bootcode. IPL3 lives in the cart, but the 6105 variant is encrypted and each CIC checks a different CRC. The algorithm is implementable; the key material is not something to include.
  • The RDP, the VI, audio and the controller. Milestone M3 onwards. Display lists do now appear — a synthetic task builds one in DMEM and DMAs it to RDRAM — but nothing rasterizes them yet, and the RSP's vector unit does not exist, so real ucode stops at its first vmov.

If a page like this showed a running Zelda title, it would be distributing someone else's game. The plan in emulator-plan.md is written around that constraint: verification uses your own dump and recorded expectations, or nothing.

03 Build and run

Needs a C11 compiler and a shell. No submodules, no generated tables, no third-party code. 

$ git clone https://github.com/HRW233/n64-player
$ cd n64-player && make
$ ./n64player your-dump.z64
file           your-dump.z64
entry          80000400
title          "..."
CIC            6102
boot           cart IPL3 at DMEM 0xA4000040
               PIF seed block is zeroed: IPL1 is not in this tree

entry point    0x80000400 after 41204 instructions
stopped        unimplemented opcode 0x4a (COP2 vector)

$ make test
150 checks, 0 failures

$ ./n64player --help
  --dump              print the ROM header and exit
  --skip-ipl3         start at the entry point instead of running IPL3
  --run N             execute at most N instructions (default 1000000)
  --trace             print each instruction while running
  --regs              print the register file at the end

n64player prints the CIC it identified, the boot path it took, whether the entry point was reached and what stopped it. When it says the seed block is zeroed, that is the missing IPL1 and not a bug report waiting to happen.

04 The plan it is being built against

  1. M0Bus, RDRAM, ROM loader, integer core, exceptions, test harness.
  2. M1Boot to RDRAM. FPU, TLB, PI DMA and vectors are done; the boot step is blocked on hardware Nintendo owns.
  3. M2RSP scalar core and OSTask dispatch: ucode DMA'd to IMEM, run to its break, display list checked in DMEM. Vector ops land with the RDP.
  4. M3RDP rasterizer, texture pipeline, table-driven combine modes, VI scanout, first frame.
  5. M4Frame-hash regression, versioned save states, determinism.
  6. M5Block translation cache, RSP fast paths — only after correctness, only with measurements.

05 Simplifications, written down

  • 4 KiB pages only. No page-mask pairs, no ASID comparison in the TLB lookup.
  • PI DMA completes synchronously. The cart-domain latency is not modelled.
  • Count counts instructions, not cycles at 93.75 MHz. Audio pitch and VI pacing will need the real thing.
  • Only the compare bit of FCR31. There is no FPU exception model yet.
  • Halting instead of guessing. COP2, LDL/LDR/SDL/SDR and LL/SC reservations stop with a named reason rather than approximating silently.

No ROMs, no keys, no bootcode — .gitignored by policy, and no test in the tree touches copyrighted data.
